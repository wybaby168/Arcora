# 安全设计、隐私和残余风险

## 保护目标

减少普通恶意归档引发的路径穿越、文件覆盖、内存 / 磁盘资源耗尽、秘密暴露和误报成功。没有安全软件能够仅凭外层路径检查保证任意编解码器对所有恶意输入绝对安全；本项目不能替代上游漏洞修复或恶意软件分析沙箱。

## 路径和写入

在 Swift 层检查完整字符串，拒绝 NUL 与控制字符，之后才传 C 字符串，避免嵌入 NUL 截断绕过。拒绝绝对路径、`..`、盘符、反斜杠 / 冒号等高风险表示，并以 Unicode NFC / 大小写折叠检查重名与父路径文件冲突。

默认拒绝符号链接、硬链接、设备、FIFO 等特殊条目。C 提取路径从已打开的根目录描述符开始，用 mkdirat / openat 和 O_NOFOLLOW 逐层创建，最终文件要求 O_EXCL。普通文件初始权限 0600，目录 0700，剥除特权位与所有权还原，尽力保留修改时间和安全可执行位。

7-Zip / RAR 是独立原生进程，但不是启用 App Sandbox 的强隔离进程。其提取先做元数据检查，在私有目录运行，运行中检查资源并在结束后再次审计。事后审计无法追溯撤销一个未知引擎漏洞已经造成的越界写入，不能描述为绝对隔离保证。解压未知高风险样本仍应使用专用隔离环境。

## 事务

所有输出先写到目标卷上的 `.arcora-UUID` 私有目录。检查引擎状态、内容、预期路径及大小之后，以独占 rename 发布。存在同名输出时自动编号或失败，绝不默默覆盖原件。

分卷以一个完整 `.parts` 文件夹原子提交。普通取消 / 错误自动清理未提交内容。进程崩溃或断电可能留有临时目录；当前没有跨启动自动清扫或崩溃事务恢复。为了避免误删，不扫描删除无法确认属于当前任务的目录。

macOS 使用 renamex_np(RENAME_EXCL)，Linux 测试使用 renameat2(RENAME_NOREPLACE)。不同文件系统、网络盘和权限组合的行为必须在目标 Mac 上实测。

## 资源与拒绝服务

默认限制展开容量 200 GiB、条目 250,000、完整目录 64 MiB、诊断保留 1 MiB、活动任务超时 24 小时。用户可调整部分安全限制。

libarchive 路径在实际数据写入前累计检查展开字节；7-Zip 路径用周期检查配合元数据和结束审计，可能暂时超过软配额。磁盘剩余空间检查有 TOCTOU 窗口，不能阻止其他应用同时填满磁盘。线程 / 字典内存估计也不是硬 RSS 限制。对极端压缩炸弹，强沙箱和系统配额仍是独立防线。

## 密码和本地数据

密码不进入进程 argv，不序列化到日志 / 任务历史 / 偏好。通过管道发送给受控进程；不使用 shell 字符串拼接。Secret 和临时 C 缓冲尽力覆写，但 Swift / AppKit 内部副本、交换内存和系统转储无法保证完全无残留。

用户请求预览时，解密后的文件会实际写入私有临时目录供 Quick Look 读取。关闭预览清理；异常退出不能保证立即清理。不要将“密码不保存”理解为“解密内容绝不落盘”。

最近文件、任务标题、输出路径和历史是本地隐私数据。设置中可清除。应用不包含广告 SDK、遥测、账户服务或运行时自动联网；手动打开官方许可网页不属于后台上传。

## 供应链

官方 7-Zip 二进制与对应源代码按固定版本和独立锁定 SHA-256 下载，校验失败即停止。不能只下载远端可被替换的校验文件而不信任本地锁文件。更新必须重新审核原始来源、许可与测试，不自动跟随 latest。

macOS 静态链接校验摘要后的官方 libarchive 3.8.9 / liblzma 5.8.3，维护者负责跟踪安全更新并重建应用。Linux 开发使用系统 libarchive。RAR 编码器不随产品分发。用户在浏览器下载官方原包后，应用先校验固定原包 SHA-256，再安全解包和校验执行文件摘要，原子写入私有目录。保留 quarantine，不关闭 Gatekeeper，不用 shell 或管理员权限，不自动下载。许可证单独保存、每次创建核验，确认框和注册状态不是法律审计。维护者需更新固定版本和摘要；不得以接受任意下载来掩盖上游兼容变化。

## 报告与发布门槛

公开发行前完成 MACOS_ACCEPTANCE.md，并保持引擎更新。发现安全问题时保留最小重现样例，记录引擎版本、OS、目标文件系统及错误；避免在公开 issue 中附带真实密码或敏感归档内容。当前交付不包含第三方安全审计或漏洞无风险保证。
